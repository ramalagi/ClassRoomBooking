How notifications flow

  1. Faculty marks a student absent.
  2. The server resolves the parent's preferred channels (per-student override → org default → opt-out).
  3. One ParentNotifications row is queued per channel (deduplicated by attendance + channel).
  4. A background worker dispatches each row through its provider. Failures retry up to 5 times.
  5. You can monitor + retry on the Notifications page.

Data retention

Attendance and notification rows older than 2 years are archived into AttendanceArchive / ParentNotificationsArchive. Reports can opt-in to include the archive via the Include archived rows checkbox.
